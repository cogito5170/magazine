# /mood — 사진 + 느낌 → 시안 한 장

사용자가 사진과 느낌(무드)을 주면 아래 순서를 **그대로** 따른다. 승인된 두 결과의 방식이다.
- **MATCH 부드러운 댄디**: `edas/mood/contemporary.py:nocturne_dandy`
- **STOP 라포**: `edas/mood/rapport.py:rapport_spread`

막히지 않는 한 사용자에게 되묻지 않는다. 해석이 갈리면 한 줄로 해석을 밝히고 진행한다.
예: "라포틱" → 라포(rapport)로 해석하고 바로 진행.

## 0. 지켜야 할 것

- **원본 파일**
  - 원본은 수정하지 않는다. 복사본으로 작업한다.
- **사진**
  - 생성하거나 지우거나 덧그리지(inpaint) 않는다.
  - 허용하는 처리: 자르기, 확대, 반전, 반복, 기하 변형(나선 등), 톤 처리(매트, 헐레이션, 블러).
  - 모든 처리를 spec JSON과 답변에 적는다.
- **카피와 수치**
  - 카피는 원문 그대로 둔다.
  - 원문의 중복·오타·시제 섞임은 고치지 말고 보고한다.
  - 지면의 숫자는 실제로 측정한 값만 쓴다(원본 크기, 확대율, 색차 등).
- **출처**
  - 이번 작업에서 실제로 확인한 출처만 인용한다.
  - 못 찾았으면 "근거 없음/관행"이라고 쓴다.
- **판단의 범위**
  - 무드는 디자인 의도이자 가설이다. 측정되었다고 말하지 않는다.
- **승인된 결과 — 절대 퇴화 금지**
  - 승인된 결과는 손대지 않는다. 새 작업은 새 파일과 새 함수로 만든다.
  - `tests/test_mood_approved.py`가 승인작을 원본에서 다시 렌더해 픽셀 해시를 비교한다. 이 테스트가 실패하면 커밋하지 않는다.
  - `edas mood render <name> --image sources/...`가 항상 `identical to the approved file`로 나와야 한다.

## 1. 접수

```sh
edas mood fonts            # pretendard / notoserifkr 둘 다 ok 여야 한다. 아니면 --install
edas mood new <slug> --image <원본경로> --mood "<무드>"
```

- 이미지가 대화에 붙어 왔으면 업로드 경로(`~/.claude/uploads/...`)를 `--image`에 넘긴다.
- 그러면 `output/<slug>/original.*`과 `brief.json`이 생긴다.

## 2. 원본 읽기

- **좌표 읽기**: `edas mood grid output/<slug>/original.* --region X0 Y0 X1 Y1 --zoom 3 -o /tmp/g.png`
  - 이 이미지를 열어 다음 좌표를 원본 px로 읽는다:
    - 사진 영역(crop)
    - 주인공·사람 박스(person)
    - 옷·소재 영역(outfit)
- **원본에 박힌 요소**: 번호 라벨, 점선 박스, 그래픽 등을 확인한다.
  - 라벨은 잘라내도 된다.
  - 점선 박스처럼 사진에 박힌 것은 그대로 둔다.
- **카피 전사**: 모든 카피를 확대 crop으로 확인해 글자 그대로 옮긴다.
- **데이터 파일**: 위 내용을 `edas/mood/spreads/<slug>.py`에 적는다.
  - 형식은 `match.py`(Photo 목록) 또는 `stop.py`(CELLS)를 따른다.
  - 측정 방법은 docstring에 쓴다.

## 3. 무드 해석과 조사 (검색 2~4회, 한 번에 병렬로)

- **(a) 무드의 근거**: 그 무드 개념을 구성 요소로 나눈 1차 문헌이나 학술 출처를 찾는다.
  - 예: 라포 = 주의, 긍정, 조율(Tickle-Degnen & Rosenthal 1990), 대인 거리(Hall 1966).
- **(b) 현대 예술 기법**: 이 무드와 내용에 맞는 기법의 원작과 출처를 찾는다.
- **사람 사이 연구를 지면에 옮길 때**: "디자인 비유, 검증 안 됨"이라고 밝힌다.

## 4. 설계 레시피 (승인된 결과를 만든 것)

### 강도

1라운드 수준을 맞춘다. 과감하고, 구조적 아이디어가 하나 강하게 있고, **읽힌다**.

| 반려된 방향 | 이유 |
|---|---|
| 정돈된 그리드형 | 무드·감각과 거리가 멀다 |
| 기법을 겹겹이 쌓은 것 | "볼 수 없을 정도로 과감" |
| 기법 하나만 남긴 차분한 정제본 | "아니야" |

### 구조

카피가 말하는 아이디어 하나를 지면 구조로 만든다.
- **NOCTURNE**: 왼쪽 면 전체를 주인공 사진으로 채우고(풀블리드), 접히는 선을 따라 세로 제목, 작은 프린트 세 장.
- **STOP**: "멈춘 사람"만 선명하게, 여섯 명의 중심을 하나의 눈높이 선에 정렬, 사진들이 어깨를 맞대듯 겹침.

### 시리즈 DNA (매번 넣는다)

- **Richter식 줄무늬**: 사진의 한 열을 나누고, 뒤집어 붙이고, 반복해(divided/mirrored/repeated) 제목 안에 채운다(`contemporary.richter_strip` + `defamiliar.text_mask`).
  - 줄무늬 원천은 무드에 맞는 사진 부분에서 고른다. 니트(댄디), 가게 불빛(라포).
- **가난한 이미지 정직성(Steyerl)**: 원본 크기와 확대율을 지면에 적는다.

### 기법 팔레트 (2~3개만 고른다)

| 함수 | 효과 |
|---|---|
| `defamiliar.slit_scan` | 시간, 잔상 |
| `contemporary.halation` | 따뜻한 빛 번짐 |
| `contemporary.matte` / `rapport.warm_matte` | 바랜 인화 |
| `rapport.motion_outside` | 주체만 선명하게 |
| `final.progressive_blur` | 점점 흐려지는 블러 |
| `contemporary.ruff_jpeg` / `soft_jpeg` | 최대 압축 그림자(Ruff) |
| `defamiliar2.pixel_stretch` | 가장자리 늘이기 |
| `defamiliar.misregister` | 인쇄 어긋남 |

### 무드 레이어

조사한 구성 요소를 아래 네 가지에 하나씩 대응시킨다:
- **팔레트**: 가능하면 원본에서 색상(hue)을 샘플한다.
- **서체**
- **처리 강도**
- **배치**

| 무드 | 종이 / 잉크 | 서체 | 처리 |
|---|---|---|---|
| 부드러운 댄디 | 아이보리 (233,227,216) / 웜 차콜 (58,54,50), 토프·카멜 | Noto Serif KR Light/SemiBold, Caladea Italic 캡션 | 매트 24/240, 헐레이션, 슬릿스캔 amp 40, 토프 JPEG 그림자, 얇은 테두리 |
| 라포 | 크림 (239,231,217) / 웜 브라운 (70,52,42), 원본 라벨 색상의 테라코타 | Noto Serif KR, Caladea Italic | 주체 밖 모션블러, 따뜻한 헐레이션·매트, 눈높이 정렬, 겹침 그림자 |

### 타이포

- 한글은 Pretendard(`final.kr`) 또는 Noto Serif KR(`contemporary.serif_kr`)만 쓴다.
- JetBrains Mono에는 한글이 없다. 섞어 써야 하면 `final.mixed`를 쓴다.
- 지면에 분석용 숫자를 늘어놓지 않는다. 공정 설명은 한두 줄로 작게 쓴다.

### 캔버스

원본 비율을 따르고 폭은 2000px로 한다. 여백 40~56px.

## 5. 만들기

- **코드 위치**
  - `edas/mood/<slug>.py`에 `<slug>_spread(...) -> (page, spec)`를 만든다.
  - 기존 함수를 고치지 말고 import해서 재사용한다.
- **spec 내용**
  - 무드 의도, 처리 목록과 수치, 출처, 카피 관련 보고.
- **등록**
  - `edas/mood/spreads/__init__.py`의 `WORKS`에 등록한다.
  - 원본은 `sources/`에 둔다.
- **렌더 위치**
  - `output/<slug>/`

## 6. 눈으로 확인하기 (2~4회 반복)

**품질 기준선**: 전달하기 전에 새 시안을 `docs/approved/*.jpg`(승인작 3장)와 나란히 Read로 본다.
- 과감함, 완성도, 무드의 분명함이 승인작보다 낮으면 전달하지 않고 고친다.

축소본을 Read로 직접 보고, 세부는 확대 crop으로 본다. 확인할 것:
- 글자 충돌, 잘림, 지면 밖으로 나간 라벨
- 복잡한 사진 위에서 안 읽히는 글자(필요하면 scrim)
- 두부 글자(□), 고정폭 글꼴의 한글
- 겹침에 가려진 주인공·사람
- 줄무늬 제목이 회색 단색으로 보이지 않는지(원천 열을 바꾼다)

## 7. 전달

- **시안은 한 장.** 변형은 요청할 때만 만든다.
- **파일**: `SendUserFile`로 PNG와 PDF를 보낸다.
- **답변(한국어)**:
  1. 해석 한 줄
  2. 표: 무드 구성 요소 → 지면 장치
  3. 서체
  4. **알려 드릴 점**: 해석, 원문 문제, 사진 처리 목록, 해상도 한계, 무드는 가설이라는 점
  5. 출처 링크
- **기록**:
  - `docs/mood_techniques.md`에 한 단락 추가한다.
  - 테스트를 실행한다(`python3 -m unittest discover -s tests -t .`).
  - 승인 해시가 그대로인지 확인한다(`edas mood render ...`).
  - 현재 브랜치에 커밋하고 push한다.

## 8. 피드백 받기

| 피드백 | 대응 |
|---|---|
| "좋은데 무드 바꿔" | 구조와 기법은 두고 **무드 레이어만** 바꾼다. 새 함수로 만든다. |
| "더 과감하게" / "정제해" | 4절의 강도 표 사이에서 한 단계만 움직인다. |
| "이게 맞아 / 고대로" | `approved.json`에 픽셀 해시를 추가하고 `WORKS`에 등록한다. |
